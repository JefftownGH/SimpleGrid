# SimpleGrid 与 NoFences 上游版本差异

本文面向希望评估、审阅或继续维护本项目的用户和开发者。对照基线是 [Twometer/NoFences](https://github.com/Twometer/NoFences) 上游项目；当前维护实现以 `source/` 为准。

## 1. 项目定位

SimpleGrid（简单格子）不是全新重写，也不是上游官方发行版。它保留了 NoFences 的 Windows Forms、透明桌面窗口、XML 围栏模型和 Shell 集成基础，在此之上补充交互能力并修复长期运行问题。

主要目标是：保持程序轻量；让高 DPI、多围栏和大量快捷方式场景更可靠；避免 Shell 与图标解析阻塞界面；让排序、删除、迁移和保存结果可预测、可恢复；形成可公开构建和继续开发的源码结构。

## 2. 拖拽与排序

上游可以接收外部文件拖放，但不提供完整的围栏内排序、跨围栏移动和插入位置反馈。当前实现：

- 用 `InternalDragItem` 区分内部拖拽和外部文件拖放。
- 超过 Windows 系统拖拽阈值后才开始拖动，减少误操作。
- 支持同围栏任意位置重排和跨围栏移动。
- 用蓝色插入线显示目标位置。
- 目标已经存在相同路径时去重。
- 锁定相关围栏时拒绝移动。

内部移动只改变围栏元数据；由于新导入项目存放在中央 `Items` 仓库，跨围栏移动不需要再次复制物理文件。

## 3. 高 DPI 与命中一致性

旧实现的绘制换列与鼠标命中可能采用不同的宽度推导，在 125%、150%、175% 或 200% 缩放下，像素取整会造成“屏幕画成四列，点击却按三列计算”。

当前实现让图标绘制、换行、单击、双击、拖动起点、放置位置和插入提示线共享同一个列数与物理尺寸模型。程序还通过 `RenderedItem.ModelIndex` 把屏幕上的可见项目映射回原始 `Files` 列表；即使列表夹有失效路径，用户看到和操作的仍是同一个项目。

## 4. 快捷方式启动与界面响应

上游主要通过 Windows Shell 打开项目，某些 Shell 扩展、损坏快捷方式或 Explorer 状态可能让调用长时间阻塞。当前 `FenceEntry.Open()`：

1. 在后台任务中执行启动流程。
2. 使用 `WScript.Shell` 解析 `.lnk` 的目标、参数和工作目录。
3. 对有效 EXE 目标使用 `UseShellExecute=false` 直接启动。
4. 对文件夹、协议和无法解析的特殊项目回退到 Windows Shell。
5. 明确释放 COM 快捷方式对象。

这降低了 NoFences UI 线程与 Explorer Shell 的耦合，但无法保证第三方目标程序本身一定能正常启动。

## 5. 图标、缩略图与 GDI 资源

当前版本把高成本的 Shell 高清图标获取移出 UI 线程：

- 缓存未命中时立即返回占位图。
- 最多两个后台任务并发加载 Shell 图标。
- 路径缓存使用 Windows 大小写不敏感比较。
- 缓存和待处理集合有明确锁保护。
- 图标完成后通过窗口消息请求重绘。
- 图片缩略图以共享读取方式打开，避免整文件额外复制。
- HICON、Bitmap、Icon、Brush、Pen 和 Font 等资源均有明确释放路径。

鼠标移动触发的重绘约以 32 ms 为最小间隔，窗口移动与缩放保存使用 UI 计时器节流。

## 6. 快速右键菜单

完整 Windows Shell 菜单需要加载第三方扩展，首次打开可能较慢。当前版本将普通右键改为 SimpleGrid 快速菜单：

- 菜单弹出前通过实际布局命中并锁定目标路径。
- 鼠标离开围栏后，删除仍作用于正确项目。
- 删除会清理同一路径的大小写变体和重复元数据记录。
- “在资源管理器中打开”会打开目录并选中对应项目。
- `Shift + 右键` 保留完整 Windows Shell 菜单。

删除项目只移除围栏记录，不删除物理文件。

## 7. SimpleGrid 自有 Items 仓库

上游和早期维护版直接保存外部绝对路径。桌面整理目录被移动、卸载或断开后，围栏就会出现失效项目。当前 `FenceManager.ImportItem()` 会在外部项目拖入时：

1. 验证源文件或目录存在。
2. 为项目生成独立随机容器目录。
3. 将文件或整个目录复制到 `%LOCALAPPDATA%\SimpleGrid\Items`。
4. 只有复制成功后才把新路径加入围栏。
5. 复制失败时记录诊断信息并清理未完成容器。

如果路径本来就在 `Items` 内，则直接复用而不重复复制。这个设计让 SimpleGrid 的活动内容不再依赖旧 DeskBox 或桌面文件位置，同时保留外部原件。

## 8. XML 保存与启动容错

- 先序列化到同目录 `.tmp` 文件，关闭写入流后再原子替换正式 XML。
- XML 反序列化完成后先关闭读句柄，再创建窗口。
- 一个围栏加载失败时记录日志并继续加载其他围栏。
- 窗口构造期间抑制位置和尺寸保存，避免初始化事件覆盖旧布局。

## 9. 生命周期与桌面集成

- 使用命名 Mutex 保证单实例。
- 围栏窗口从 Alt+Tab 隐藏并贴合 Windows 桌面层。
- 收到 `TaskbarCreated` 后重新设置层级，以适应 Explorer 重启。
- 外部关闭请求通常被拦截；Windows 正常关机时允许关闭。
- 关键启动、关闭和异常信息写入 `%LOCALAPPDATA%\SimpleGrid\app_diag.log`。

开机启动方式属于部署环境，不由当前 EXE 自动创建。公开发行版仍需要后续提供安装器和明确的启停选项。

## 10. 尚未解决的问题

- 缓存缺少容量上限和统一的文件修改时间失效策略。
- 绘制流程仍会检查文件系统路径，慢速或失联盘符可能影响响应。
- `Items` 中的无引用副本不会自动垃圾回收。
- 缺少正式安装器、代码签名、CI 和自动发布流程。
- 桌面层交互的自动化覆盖有限，真实鼠标拖拽仍需人工验收。

这些限制会在 README 中公开说明，不把计划中的能力描述为已完成。
